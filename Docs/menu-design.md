# UOpenGolf — Fairway interface

Open `menu-prototype.html` in a browser for the interactive design. It uses an existing project screenshot, works offline, and saves demonstration preferences locally. It is a design artifact, not a connected Unreal settings implementation.

## Art direction and navigation

Quiet, premium sports presentation: charcoal #121917, ivory #F0F2E9, muted sage #ACC89A. Let the course occupy the screen. Use a subtle dark gradient for readability, thin rules, generous whitespace, restrained 4px corners, and a single accent. Avoid card grids, glossy buttons, heavy borders and ornamental icons. Use a licensed sans-serif with regular text and medium headings; minimum 18px at 1080p, scalable to 150%. Focus uses a visible sage outline and must never rely on color alone. Transitions are 160ms fades, disabled with reduced motion.

Home: Training, Settings, Exit. Exit asks "Exit UOpenGolf?" with Yes and Cancel. Show the project version in the lower-right corner on home and settings screens (currently v0.0.6, sourced from ProjectVersion in Config/DefaultGame.ini). Future course selection, competitions and multiplayer appear only when implemented. Home shows active local player and actual monitor connection state. Training leads to the current training range, with existing hole practice available within training. Pause (Escape during Training) uses the same shell: "Paused" / "Training" with Resume training, Settings, Main menu and Exit to desktop. Main menu asks "Return to the main menu?" (the training session ends, recorded shots are saved, the launch monitor stays connected) and reloads the map into the main menu; Exit and Exit to desktop ask "Exit to desktop?". Both confirm with Yes / Cancel; confirm any action that loses a round. Escape closes the topmost dialog, then settings, then opens pause; never immediately exits the application.

Settings: category rail, scrollable grouped rows, contextual help, persistent Apply / Discard footer. Show changed count and Reset All action. Search labels and descriptions across categories. Controller bumpers switch category; D-pad navigates rows; left/right adjusts discrete values; A confirms; B backs out. Preserve focus and scroll when returning. Touch targets are at least 48px. Keep settings usable at 1280×720, 1080p, 4K, ultrawide and simulator projector aspect ratios with a bounded content width and safe margins.

## Settings inventory

All entries below are proposed product scope; existing engine/game capabilities still need UI integration. Hide unavailable capabilities or disable them with a concrete reason. Never present a setting that silently does nothing.

Categories appear in the settings rail in the order of this table.

| Category | Controls |
| --- | --- |
| Player | Player handedness, preferred club, club bag and carry references; automatic club suggestion; distance/short-distance, speed, wind and temperature units; aim sensitivity and fine aim; preferred assistance preset; auto tee delay; shot confirmation/retry behavior. Handedness must not mirror measured launch data. |
| Simulator | Supported device selection (Square Home or an Open Connect connector, with port and LAN access; these connection choices apply and save immediately, outside Apply/Discard/Reset All), connect/disconnect, actual status/battery when reported, reconnect preference, connection diagnostics; Square spin mode (Measured or Calculated, default Measured), mapped to the device ball-detection spin mode with calculated values explicitly labeled; shot readiness sound; handedness/placement guidance; projector alignment and physical screen calibration. Calibration is a guided flow with documented units and validation, not an arbitrary physics multiplier. |

Any future telemetry is disclosed and configurable. |

Default presentation: current engine video values until hardware detection; motion blur off; restrained tracer; readable HUD; existing physics and shot rules preserved. Simulator measurements remain authoritative. Assistance presets summarize their effects. Do not silently alter carry, spin or ball physics through difficulty settings.

## Unreal integration contract

- Retain the project's Slate UI approach. Add shared theme tokens and reusable setting rows alongside existing HUD widgets. Mount the menu through AUOpenGolfHUD above existing controls. The player controller owns modal focus/input routing and suppresses shot, aim and placement commands while a modal menu has focus. Decide explicitly how incoming launch-monitor shots are rejected while menus are open; show a readiness state and never replay queued shots unexpectedly.
- Use UGameUserSettings for supported display/scalability settings. Keep device-specific graphics and simulator calibration local to the machine; persist player preferences separately with a versioned schema. Game Defaults create a session snapshot and never rewrite a running round.
- Maintain saved, draft and preview state. Apply validates and saves atomically per settings domain; report individual failures and preserve drafts. Discard reverses previews. Reset All restores defaults across all editable settings categories in the draft; Apply commits them and Discard cancels the reset. It does not alter recordings or the in-game recording state. Display changes require Keep/Revert with a 15-second countdown and automatic rollback; recover a known-good mode after failed startup. Tag restart-required settings.
- Bind supported settings to existing wind, camera, HUD and launch-monitor services. Add missing runtime capabilities incrementally rather than exposing inert controls. Capability checks govern HDR, upscalers, ray tracing, refresh rates and device fields.

## Acceptance

Verify keyboard and controller navigation, focus restoration, screen-reader labels where supported, readable contrast, scaling and safe-area layouts. Verify draft/apply/discard/defaults and persistence, corrupt preference recovery, display timeout rollback, device disconnect/reconnect, unsupported graphics hardware, incoming shots while menus are open. Verify changes to Game Defaults do not affect an active ball flight or round. Compare home, video, simulator and pause screenshots at 720p, 1080p, 4K and ultrawide. The browser prototype demonstrates navigation and preferences only; it does not validate engine behavior or GPU capabilities.

Shot recording remains controlled exclusively by the existing in-game F9 action for now. Settings provides instructions only: no recording toggle, persisted recording preference, or change to the current recording state during Apply or Reset All.

## Gimmie visualization and shared in-game HUD

Training in the browser prototype opens an illustrative HUD preview. The preview radius selector demonstrates Off, 3, 5, 8 and 10 ft without changing saved settings; entering the preview reads the applied Game Defaults. The ring is an ellipse only to illustrate perspective in the browser.

In Unreal, draw a world-space circle centered on the cup at the flag base, using the active session's gimmie radius (feet converted to centimeters). Use a thin sage outline and a very faint sage fill, projected onto the green with depth testing and a small surface offset to prevent flicker. Follow terrain height around the circumference; never draw a floating screen-space oval. Hide the ring when gimmies are Off, when there is no valid cup, or when the mode does not support concessions. It is visual-only and has no collision. Pin lifting does not move its center. Its size must match the horizontal distance used by scoring exactly; eligibility still requires the ball to stop on the green. Explain that the concession adds one putt. Keep the cup and ball readable through the fill.

Apply the menu theme to all existing in-game HUD surfaces: shot and launch-data tiles, wind indicator and slide-out, play/placement controls, pin-distance label, score and hole-completion banners, replay selector, connection/battery status, and F9 recording status. Share charcoal, ivory, muted-text and sage tokens plus fonts, spacing, corner radii, thin borders and focus states through a common theme. Preserve semantic warning/error distinctions with text or icons as well as color. Use translucent charcoal panels over the course, ivory primary values, muted labels and sage selections. Retain current functions and recording controls; Settings contains recording instructions only.

Validate ring radii at 3/5/8/10 ft and Off against measured world distances, slope conformity, depth occlusion, pin lift, camera zoom, high contrast, active-session defaults and scoring boundary tests. Capture all HUD panels against bright sky and dark foliage at supported resolutions to verify readability and visual consistency.
